# Этап 3 — жизненный цикл плеера и модальных экранов

Дата: 20 октября 2026. База: `6ee1985`, ветка `codex/stable-playback-lifecycle`.

## Изменения

- `PlaybackSession` владеет одним preview UIView, состоянием, прогрессом и таймером. Открытие Edit/Export не заменяет ни preview, ни его engine.
- Runtime/правки сначала готовятся в отдельном кандидате; действующий engine заменяется после успешной подготовки. Ошибка не останавливает старое воспроизведение и не сбрасывает кадр.
- Для web-кандидата ожидается настоящий DOMLoaded, с отменой и лимитом 10 секунд. Поздний результат после Back/новой загрузки не устанавливается.
- Completion четырёх native runtime и web возвращает Play Once в остановленное состояние и выключает polling. Pause/Stop/замена engine отсекают старые completion.
- Шаг по кадру и seek ставят воспроизведение на паузу. В неактивной сцене таймер выключен; при возвращении возобновляется только ранее игравшая анимация.
- Все sheets используют один `SheetRoute`. Renderer Test ставится в очередь до настоящего `onDismiss` настроек. Выбор ресурсов также открывается после dismiss отчёта.
- Асинхронное применение правок/выбор sample ожидают готовность кандидата; закрытие блокируется только на время операции. Внешний вид шторок, таббара, кнопок и отступы не переделывались.

## Ревью

Независимый read-only reviewer нашёл две P2-гонки. Обе воспроизведены до исправлений: 2 теста / 3 проваленные проверки (`/tmp/flippie-stage3-review-red.log`).

1. Поздний runtime-switch мог очищать состояние более новой операции и показывать ошибку после Back. Состояние переключения теперь в session, все завершения проверяют поколение; ожидаемая отмена не показывает ошибку.
2. Изменение draft-скорости во время асинхронного Apply расходилось с документом. Apply фиксирует один снимок правок, коммитит его скорость и блокирует редактирование до завершения; rollback остаётся в одной операции.

После одного прохода исправлений полный набор 73/73 и device build прошли. Повторного независимого sign-off не заявляем.

Первый неуспешный UI-прогон не используется как доказательство: тестовый UIHostingController получал неактивную scenePhase, старый тестовый процесс ещё завершался. В исправленном harness явно задана активная сцена; изолированные UI-тесты, затем оба полных набора прошли. Системный сбой запуска Busy потребовал перезапуска только тестового симулятора, без стирания данных.

## Границы доказательства

UI-прогон управляет тем же координатором, что кнопки, программно; реальные жесты пальцем и физический iPhone здесь не проверялись. Покадровый порог ищет полноэкранную белую вспышку, не доказывает отсутствие любых артефактов на всех устройствах.

Готовность/cancellation frame и snapshot continuation, Unicode в JS, absolute timeline с ненулевым `ip` и настоящий web autoReverse остаются этапом 4. Не выдаём эту работу за исправление всех web/export дефектов.

Сборка установлена и запущена на пользовательском iPhone 18 Pro / iOS 27.0; снимок `/tmp/flippie-stage3-iphone18pro.png`. Push/merge/PR не выполнялись. Дальнейшие этапы не начинались.

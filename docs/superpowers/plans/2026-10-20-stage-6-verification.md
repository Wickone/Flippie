# Этап 6 — сохранение проекта и история применённых правок

20 октября 2026. База `b4561ff`, ветка `codex/project-persistence`.

## Результат

Последний проект автоматически восстанавливается из Application Support при новом запуске. Исходные JSON-байты, относительные ресурсы, правки цветов/фона/скорости, выбранный runtime и loop mode переживают уничтожение старых in-memory объектов. Восстановление не включает автоматический Play и не заменяет уже открытый документ.

`FlippieProject` — Codable manifest schema 1. JSON исходника хранится отдельно от `AnimationEdits`; пути внутри пакета относительные. `document.assetBaseURL` явно отделён от расположения original.json и передаётся native/web preview, сравнению и экспорту. Поэтому перенос контейнера при обновлении/переустановке приложения не зашивает старый абсолютный путь в manifest.

## Запись и владение ресурсами

- `ProjectStore` выполняет I/O вне MainActor. Общая process-local блокировка сериализует независимые экземпляры store; очередь координатора сохраняет неизменяемые снимки в порядке запросов.
- Новая immutable source generation полностью создаётся до единственного commit point — атомарной записи `project.json`. До этого предыдущий manifest и его ресурсы не меняются. Поздняя запись старого документа не меняет пути нового открытого документа; устаревшая revision явно отклоняется.
- Копируются только реально упомянутые image/media/font файлы, а не весь каталог импортера или app bundle. Для изображений используется тот же первый декодируемый fallback, что и в плеере. Исходный JSON не переписывается и не смешивается с edits.
- Исходник ограничен 50 MiB, metadata — 2 MiB, отдельный resource — 50 MiB, ресурсы — 300 MiB и 4096 записей файлов/каталогов. Path traversal, symlink-компоненты, неверные цвета/скорость, повреждённый JSON и неизвестная schema не считаются успешной загрузкой.
- До commit staged assets проверяются теми же правилами, что и при load: случай 2049 файлов в 2049 папках отклоняется до замены предыдущего manifest.
- Сохраняются current source, один предыдущий неиспользуемый source и все sources, на которые есть in-process lease живого документа/очереди. Это защищает открытые изображения другого окна от очистки. Lease не сериализуется; после перезапуска единственным источником истины остаётся manifest.
- Остатки `.staging-UUID` от прерванного процесса удаляются при следующем сохранении под той же блокировкой. При штатной ошибке/отмене staging удаляет defer.
- Повреждённый предыдущий пакет не перезаписывается молча. В Error доступно явное действие **Keep damaged copy and start fresh**: весь пакет перемещается в `Recovered-UUID.flippie`, после чего можно сохранить новый импорт. Валидный пакет и future schema таким способом заменить нельзя. Сохранённая повреждённая копия не удаляется автоматически.

## Edit и жизненный цикл

- Поля sheet — локальный draft. Cancel или swipe без Apply не меняют документ и диск. Изменение Draft и сохранение applied state разделены; отдельный **Save applied changes** нужен для повторной записи после I/O-ошибки.
- Нативные Undo/Redo отменяют/повторяют до 50 применённых edit states текущего документа. Новая правка удаляет redo-ветку. Runtime/loop — самостоятельные сохраняемые настройки, не часть undo-истории.
- На время Apply/history controls блокируются. Чекпойнт восстанавливает edits и историю при ошибке подготовки/сохранения; preview подготавливается обратно, скорость синхронизируется. Поздний failure старой операции не накладывает старые правки на новый документ.
- Фоновое автосохранение не может захватить provisional Apply. Только явная запись после успешной подготовки renderer получает pending edits. Фоновому сохранению предоставляется системный background task; истечение срока отменяет запись до commit.
- Восстановление запускается один раз. Импорт отменяет незавершённое восстановление. Внедрённые в обычные UI-регрессии документы не используют app-global persistence без специально переданного изолированного координатора.
- Preview UIView, нативные detents, таббар и дизайн экрана не менялись. В Edit добавлены только системные кнопки истории и статус/повтор сохранения.

## Границы

- Это локальный **последний рабочий проект**, не библиотека проектов, cloud sync, Save As или merge между окнами. Конкурирующая устаревшая revision показывает ошибку, а не перезаписывает более новую.
- Undo/redo не восстанавливаются после перезапуска: сохраняется применённое состояние. Позиция playhead/состояние Play не сохраняются; открывается начало в Pause.
- Восстановление schema 1 проверено новым экземпляром store/document и переустановкой simulator build с сохранённым контейнером. Реальная App Store миграция будущих schema, аппаратное устройство и power-loss durability не доказаны. `.atomic` — защита commit/rename, не обещание fsync при потере питания.
- Background execution ограничен iOS. Force kill до первого завершённого commit не может сохранить изменения только из памяти; физическая latency истечения background task не измерена.
- Не заявляются полноценное воспроизведение audio/fonts во всех runtime, iCloud/provider permission coverage, все native gestures/accessibility layouts или замеры пиковой памяти/производительности на лимитах. Копирование существующего файла не означает поддержку его выполнения.
- Сам ProjectStore не отправляет данные в сеть; поддержку внешних ресурсов существующих renderers этот этап не расширяет. Резервные `Recovered` требуют явного дальнейшего управления пользователем; автоматическое удаление повреждённых данных не добавлено.
- Работа остаётся в локальной ветке; push, merge и PR не выполнялись. Этап 7 требует отдельного запроса.
